# Project instructions

The owner authorizes normal commits, pushes, and improvements in this repository
without another permission request. Do not force-push or erase existing work.

The objective is a strong **current-patch Solo Battlegrounds AI**, with reusable
learning across rotations. A positioning model is one component, not the finished
player. Report that boundary clearly.

- Check official patch notes, the official card gallery, and current hotfix/known
  issue notices when refreshing the ruleset. Client data alone can miss bans.
- Pin engine packages and card data. Record hashes, source dates, and exact
  training/evaluation scope in artifacts. Do not relabel old data as current.
- Keep active shop pools separate from referenced tokens, goldens, enchantments,
  and cards that are only generated by effects. An old definition in reference
  data is never sufficient permission to offer it in the shop.
- Never silently replace missing effects with vanilla stats or no-ops. Full-game
  training remains blocked while required transitions are unimplemented.
- Preserve learned representations across rotations; compare warm starts with
  fresh models at equal compute before claiming a transfer benefit.
- Split related decisions by scenario/game before training. Use separate final
  evaluation RNG streams, fixed opponents, uncertainty estimates, and saved
  readable traces. Do not promote based on training accuracy.
- Do not imply ongoing training unless a durable job actually exists and its
  running state was checked. Keep failures and limitations visible.
- The user requires realistic actions per second and a finite action budget
  derived from each player's actual remaining recruit timer. Use the shared
  timed recruit wrapper; never allow free macros, budget resets within a turn,
  or automatic hand plays. Include remaining time/actions in policy inputs.

Use `python -m unittest discover -s tests` with `PYTHONPATH=python` for Python
tests and `npm test` for the simulator integration. Keep tests focused on engine
correctness, data integrity, leakage, and measurable training behavior.
